# Midscene AI 自动化测试平台 — 数据库设计文档

**版本**：1.0  
**更新日期**：2026-02-13  
**数据库**：MySQL 5.7+ / 8.x  
**ORM**：Django 6.x Models  

---

## 1. 概述

本系统使用 Django 管理数据，持久化层采用 MySQL。主要业务实体为：测试用例（TestCase）、生成脚本（GeneratedScript）、执行批次（TestRun）、执行结果（TestResult）。下表为 ER 关系简要说明。

| 实体 | 说明 |
|------|------|
| TestCase | 从 Excel 解析出的测试用例 |
| GeneratedScript | 某用例对应的 AI 生成 YAML 脚本 |
| TestRun | 一次批量执行任务 |
| TestResult | 某次执行中单个用例的执行结果 |

---

## 2. 表结构

### 2.1 workflow_testcase（测试用例）

对应模型：`workflow.TestCase`。用于存储从 Excel 上传并解析出的测试用例。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | INT | PK, AUTO_INCREMENT | 主键 |
| case_id | VARCHAR(50) | UNIQUE, NOT NULL | 用例编号（来自 Excel，唯一） |
| title | VARCHAR(200) | NOT NULL | 用例标题 |
| description | TEXT | 可空 | 描述 |
| preconditions | TEXT | 可空 | 前置条件 |
| steps | TEXT | NOT NULL | 操作步骤（原始文本） |
| expected_result | TEXT | NOT NULL | 预期结果 |
| priority | VARCHAR(20) | 默认 'Medium' | 优先级 |
| created_at | DATETIME | 自动 | 创建时间 |

---

### 2.2 workflow_generatedscript（生成脚本）

对应模型：`workflow.GeneratedScript`。与 TestCase 一对一，存储 AI 生成的 YAML 脚本及生成状态。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | INT | PK, AUTO_INCREMENT | 主键 |
| test_case_id | INT | FK(TestCase), UNIQUE | 关联用例，一对一 |
| yaml_content | TEXT | NOT NULL | 生成的 YAML 内容 |
| status | VARCHAR(20) | NOT NULL | pending / generating / completed / failed |
| error_message | TEXT | 可空 | 生成失败时的错误信息 |
| created_at | DATETIME | 自动 | 创建时间 |
| updated_at | DATETIME | 自动 | 更新时间 |

---

### 2.3 workflow_testrun（执行批次）

对应模型：`workflow.TestRun`。表示一次批量执行任务。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | INT | PK, AUTO_INCREMENT | 主键 |
| start_time | DATETIME | NOT NULL | 开始时间 |
| end_time | DATETIME | 可空 | 结束时间 |
| status | VARCHAR(20) | NOT NULL | pending / running / completed / stopped |
| total_cases | INT | 默认 0 | 本批次用例总数 |
| passed_cases | INT | 默认 0 | 通过数 |
| failed_cases | INT | 默认 0 | 失败数 |

---

### 2.4 workflow_testresult（执行结果）

对应模型：`workflow.TestResult`。表示某次执行（TestRun）中某一个用例的执行结果。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | INT | PK, AUTO_INCREMENT | 主键 |
| run_id | INT | FK(TestRun), NOT NULL | 所属执行批次 |
| test_case_id | INT | FK(TestCase), NOT NULL | 关联用例 |
| status | VARCHAR(20) | NOT NULL | pending / running / success / failed / skipped |
| start_time | DATETIME | 可空 | 开始时间 |
| end_time | DATETIME | 可空 | 结束时间 |
| duration | FLOAT | 默认 0.0 | 耗时（秒） |
| log_content | TEXT | 可空 | 执行日志 |
| error_message | TEXT | 可空 | 失败原因等 |
| screenshot_path | VARCHAR(500) | 可空 | 截图路径 |
| video_path | VARCHAR(500) | 可空 | 录像路径 |
| report_path | VARCHAR(500) | 可空 | Midscene HTML 报告路径 |

---

## 3. 实体关系

```
TestCase (1) ----< (1) GeneratedScript
    |
    | (N)
    v
TestResult (N) >---- (1) TestRun
```

- **TestCase ↔ GeneratedScript**：一对一，一个用例对应一个生成脚本（可无）。
- **TestRun ↔ TestResult**：一对多，一次执行对应多条结果。
- **TestCase ↔ TestResult**：多对多通过 TestRun 关联，即同一用例可在不同批次中多次执行，产生多条 TestResult。

---

## 4. 索引与迁移

- Django 默认对主键、外键建立索引；`case_id` 为 UNIQUE 会自带唯一索引。
- 新增/修改表结构请使用 Django 迁移：  
  `python manage.py makemigrations workflow`  
  `python manage.py migrate`

---

## 5. 配置说明

数据库连接由 `backend/backend/settings.py` 读取环境变量（推荐使用 `.env`）：

- `DB_NAME`：数据库名（默认 midscene_workflow）
- `DB_USER` / `DB_PASSWORD` / `DB_HOST` / `DB_PORT`：连接参数

字符集建议使用 **utf8mb4**，排序规则 **utf8mb4_unicode_ci**，以正确存储中文及 emoji。
